# Reply elements: the evidence (step 1)

Written before any design. 22 replies: the final reply in each of the 20 eval cases' cassettes on main (`tests/cassettes`, `replies-main.txt`), and the two window-chat cases on PR #115 (`replies-window-chat.txt`). Every one is the model's own reply to a fixture world: no live data.

What each reply needed to show. A number is how many; ✓ is present.

- **Item ref:** names an item (a Jira key, a file, a Slack message). "+state" means the agent also wrote its title, status or assignee in prose next to the key.
- **Oriel ref:** names a thread, change set or workstream.
- **Picked list:** a short list of items the agent chose.
- **Read list:** a list that is a read's whole answer, or one filter of it, so 0030's block would do.
- **Compare:** two or more values set side by side.
- **Quote:** synced text quoted word for word.
- **Warning:** a paragraph flagged as something the user must know: an injection, a contradiction, a risk.
- **Offer:** a next step the agent offers to take.

## What it says

1. **References are the everyday need.** 18 of 22 replies name an item, and 8 name a thread, change set or workstream ("this change set" counts). Only #3 could link one, and it did so with a 26-character ID copied into an address.
2. **The agent restates what Oriel already knows.** 14 replies follow an item's key with its title, status, owner or estimate in prose: "SYN-54 ("Cancellation alert sent…", still in To Do)". That is output tokens, it goes stale as the item moves, and nothing checks it. A key alone (#15, "**SYN-13**") is cheap but tells the user nothing and doesn't open.
3. **Files and Slack messages have no handle a reader can use.** The agent writes "meeting-notes" or "Rowan Pike in #weather-disruptions, 15 Sep 2026 at 15:30 UTC" (#4–#9, #13, #19). Neither opens the item.
4. **Lists the agent picks are short:** 2 to 9 items (#2, #5, #7, #12, #15, #22), usually "key: what matters about it". Lists that are a read's whole answer (#7, #20, #21, #22) are 0030's blocks. #21 shows the cost of having both: the agent described the bars block, then repeated its four rows as a list.
5. **Quoting synced text word for word is the most common structure:** 15 of 22 replies quote, 11 of them an injection, set off as a bold "Something you should know:" or "Instructions in the ticket:" paragraph. Each reply formats it differently: a bold lead, a `>` quote, curly or straight quotes, italics (#12). This is the behaviour SPEC §8.3 and the oa-144 climb grade.
6. **Comparisons are rare and small** (#10: two replies that disagree; #19: the decision then and now; #21/#22: counts by workstream). The two numeric ones are already blocks; the others are two sentences.
7. **No reply needed** a person element (people are named in plain text, and nothing in Oriel resolves them), a date element (the agent wrote absolute dates, except #22's "10 days ago", which goes stale as the stored reply is reread), or a status element apart from an item's own.
8. **Offers of a next step** close 13 replies. They are prose, and the actions they offer exist. A button would let a reply take an action without the user asking, which 0024 doesn't allow.
