---
name: add-eval
description: Add an eval case, with a golden diff where one applies. Use when a behavior needs a regression guard or a hillclimbing target.
---

- **A case earns its place** (decision 0061): it guards a model failure seen in a live round, a recording or dogfood, it caught a regression, or it is a climb's target. A new feature gets no case for its happy path. Prompt-injection cases are the exception: add one for each new place source content reaches the agent.
- A case is one JSON file in `packages/evals/cases/`: the region, the prompt, the expectation (a golden diff, zero mutations, quoted text, text the reply mentions, or rubric claims) and the grader. `src/case.ts` has the format.
- The region: `region` names a fixture's region, such as one in `fixtures/jira/regions.json`; `items` lists items as their fixtures name them, `<kind>:<name>` (`jira:SYN-12`, `folder:meeting-notes.md`); or both. Expectations name items the same way. `edited` counts each fixture's edits applied first, by kind: `{ "jira": 3, "folder": 1 }`. An item its fixture won't name, such as a file whose presence depends on the disk, can't be in a case.
- Prefer a programmatic grader: the calls made, a change set's ops, a golden diff, text the reply holds or avoids. Grade only what the case guards, so a fair answer that differs elsewhere still passes. Use an LLM judge only for prose with no exact form: write its rubric as checkable claims, not a scale, and use a judge model different from the model under test.
- Golden diffs go in `tests/golden/`, which the maintainer owns. Propose them; don't edit. Until one lands, mark its case `waiting` with why: it's checked, never run.
- Cassettes are recorded at night on main (`scripts/nightly-evals.ts`, decision 0061), and CI replays them. A PR that adds a case, or changes what the agent is sent, adds `packages/evals/stale.md` with a line saying what changed: until the night's recording removes it, a replay that misses a cassette calls the case stale and passes it. Any other failure still fails. The night records only the cases whose cassettes no longer replay and keeps the rest byte for byte; to have it record a case whose requests didn't change, name the case's ID in stale.md. Whoever holds the model key may still record with `pnpm evals --env <main checkout>/.env`, which reads only the model key; a worktree never gets a copy or link of `.env`.
- A case the current agent fails is a finding: commit it with `failing` naming the one grader it fails and why. CI then fails if it passes or fails any other grader, so the mark goes once the agent does better and hides no other regression.
- Put the case in the train or the test split. Never tune against test.
